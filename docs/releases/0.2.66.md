# BLoader 0.2.66

## 同账号 native 能力门控

0.2.65 已将 Minecraft 可见的 XUserHandle 与 Windows native XUserHandle 解耦，但官方 GDK 只允许 Title 操作已经通过 `XUserAddAsync` 加入的用户，因此单纯在之后调用 `FindUserById` 不能可靠恢复同账号 Microsoft Runtime Token 快速路径。

0.2.66 增加安全双轨 Add：

- BMCBL 继续只传原始 XASU UToken 与公开 XUser 元数据；
- 额外传递一个非秘密 `native_system_xuid_hint`，只用于判断本地系统账号是否与 BMCBL XUID 相同；
- 只有 `native_system_xuid_hint == custom_xuid` 时，BLoader 才在 Minecraft 的首次 `XUserAddAsync` 上调用官方 `AddDefaultUserSilently`；
- 官方 AddResult 返回的 native handle 必须再经官方 `GetId` 验证 XUID 与 BMCBL 完全一致，才保存为隐藏 Runtime capability handle；
- Minecraft 始终收到 BLoader synthetic XUserHandle，不接触隐藏 native handle；
- 不同账号或无系统账号完全不调用 native Add，因此不会为 BMCBL 托管账号触发系统 Account Picker/Bootstrapper。

如果本地 XUID hint 已过期、silent Add 失败或 Microsoft 返回了其他账号，BLoader 会关闭/丢弃该 native handle，并继续建立 synthetic XUser。后续 Token 请求进入 pre-XSTS UToken 注入发现路径；在真实 UserTokens provider ABI 尚未验证前仍 fail-closed。

## UToken-only v4

启动协议升级为 `official-runtime-user-token-v4`。凭据边界仍然只有 BMCBL 账号原始 XASU UToken：

- 不传 MSA access token；
- 不传 MSA refresh token；
- 不传预生成 XSTS；
- 不传自定义 PoP 私钥；
- `native_system_xuid_hint` 只是公开 XUID 元数据，不是认证凭据。

## 预期日志

同账号且系统用户可用：

```text
BMCBL 与 Windows 系统 XUID 提示一致；正在建立隐藏 native XUser 能力句柄
隐藏 native XUser 能力句柄已验证并绑定；Minecraft 仍接收 synthetic XUser
route=same-account-native-capability
```

系统账号不同或不存在：

```text
XUserAddAsync route=bmcbl-synthetic-user
native_system_relation=different|none
system_login_ui=not-invoked
```

随后跨账号/无系统账号 Token 请求会输出 pre-XSTS Runtime marker/xref 诊断；在真实 `D + T + U -> XSTS` builder ABI 被验证之前不会借用其他系统用户的最终 XSTS。
