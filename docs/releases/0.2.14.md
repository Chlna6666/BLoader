# BLoader 0.2.14

## 主要变更

- 新增 `type: "preload"` 的 `PreLoader.dll` 优先代理加载支持，不再需要额外的 `role` 字段。
- BLoader 在旧 `native/preload-native` 预加载链之前扫描 `mods/*/manifest.json`，仅对 `type=preload` 且入口文件为 `PreLoader.dll` 的包启用优先代理语义。
- `PreLoader.dll` 成功加载后，BLoader 跳过自己的旧原生预加载遍历，由 PreLoader 继续代理加载第三方 Loader / preload DLL。
- `PreLoader.dll` 加载失败时记录 Win32 错误码、错误文本、候选路径，并自动回退到 BLoader 原有预加载器。
- 新增 `logs/preloader-status.json`，用于明确记录 PreLoader 的 `not_found / loaded / failed` 状态。
- 原生 stdout/stderr 捕获改为全局启用；无论是否启用调试控制台，第三方 `puts/printf/fprintf/std::cout` 等输出都进入 BLoader 日志链。
- 修复早期 bootstrap 日志在正式 Logger 初始化时被清空的问题，DllMain 和 bootstrap 初期日志现在会保留在 `latest.log`。
- 修复无控制台模式下 Logger 将输出重新写回已捕获 stdout、造成日志回流/重复捕获的风险。
- 控制台日志改为紧凑的 `时间 + 等级 + 模块 + 消息` 格式，移除默认显示的 seq/thread/ASCII 大边框；线程等详细信息仍保留在专项诊断日志中。
- BLoader 内部日志、第三方 native stdio、PreLoader 加载状态统一进入全局日志入口，同时继续写入 `latest.log`、archive、DebugView 和模组专项日志。

## PreLoader manifest

```json
{
  "id": "preloader",
  "name": "PreLoader",
  "entry": "PreLoader.dll",
  "type": "preload"
}
```

`PreLoader.dll` 是 BLoader 下的特殊预加载模组，不是 BLoader 的上游加载器。

## 加载顺序

```text
BLoader
  -> type=preload / PreLoader.dll
      -> success: PreLoader 接管其余第三方 preload/Loader
      -> failure: BLoader 回退到原 native/preload-native 加载链
  -> BL Mod
  -> hot-native / hot-inject
```
