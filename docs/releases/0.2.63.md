# BLoader 0.2.63

## 跨账号 Microsoft Runtime 用户凭据覆盖

0.2.62 的 BMCBL 预生成 XSTS + BMCBL PoP key 回退已撤销。该回退能够绕过 0.2.61 的跨账号 fail-closed，但不符合目标架构，因为最终 XSTS 和 Signature 不再由系统 Microsoft Gaming Runtime 产生。

0.2.63 恢复并强化目标边界：

- **BMCBL**：保留 Microsoft refresh token；向 BLoader 的一次性进程管道仅提供目标账号原始 XASU UToken、短期 MSA access token 和公开用户元数据。
- **BLoader**：跨账号时 Hook Microsoft native XUser provider 的 `XUserGetMsaTokenSilently*` slots 39/40/41，将 backing user 的 MSA 用户凭据来源替换为 BMCBL 目标账号的短期 access token。
- **Microsoft Runtime**：继续负责 Device/Title 上下文、XASU/XSTS 聚合、最终 XSTS、缓存以及请求 Signature。

## 跨账号验证

当 native backing XUID 与 BMCBL XUID 不一致时，BLoader 不再在 `XUserGetTokenAndSignature*` 入口直接失败：

1. 安装 native MSA credential hook；
2. 对官方 token 请求附加 `ForceRefresh`；
3. 调用 Microsoft Runtime 原生 slot 23/26；
4. 最终结果只在 XSTS 载荷中的 `xid` 与 BMCBL XUID 一致时放行；
5. 如果最终 XSTS 仍属于 backing user 或身份无法验证，BLoader 会先清零返回缓冲区，再 fail-closed。

这避免了“XUserGetId 显示账号 B，但 Xbox 服务实际认证账号 A”的身份撕裂。

## 诊断日志

预期关键日志：

```text
Microsoft Runtime 用户凭据覆盖桥已安装
跨账号 Token 请求进入 Microsoft Runtime 用户凭据覆盖链
已命中 Microsoft Runtime MSA 用户凭据入口
跨账号 MSA access token 已提交给官方认证调用方
跨账号官方 XSTS 身份验证通过
```

如果当前 Windows Gaming Runtime 的 token pipeline 没有经过 native MSA slots 39/40/41，最终 XSTS 身份校验仍会失败关闭，并在日志中给出 `msa_override_hits=0`；不会回退到 BMCBL 预生成 XSTS，也不会泄露 backing user 的 XSTS。

## 安全边界

- MSA refresh token 不进入 Minecraft 进程。
- 不传入 BMCBL DeviceToken、TitleToken、最终 service XSTS 或 P-256 私钥。
- MSA access token、UToken、XSTS 和 Signature 正文不写入日志。
- 一次性启动载荷继续使用 PID/父进程绑定、有效期窗口和 SHA-256 完整性校验。
