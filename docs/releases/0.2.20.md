# BLoader 0.2.20

## Remove the render readiness compatibility layer

BLoader 0.2.20 removes the legacy `render_signal` compatibility shim introduced during the transition to non-graphics delayed-Mod readiness.

Changes:

- `src/core/render/render_signal.rs` is deleted.
- `core::render_signal` is no longer exported.
- The legacy `install`, `is_installed`, `frame_count`, and `wait_for_frame` readiness APIs no longer exist.
- Delayed `hot-native` / `hot-inject` loading uses `core::runtime_ready` directly.
- No compatibility path can map legacy frame waits to `stable-window` readiness anymore.
- The real `d3d12_queue` Mod graphics interface remains available and is intentionally unaffected.

The supported readiness model remains:

- `process`: Minecraft OEP has been released.
- `window`: a visible process-owned Minecraft window exists.
- `stable-window`: the same visible Minecraft window remains present for the stability interval.

This is a deliberate breaking cleanup. Code that directly depended on `core::render_signal` must migrate to `runtime_ready` instead of relying on a legacy frame/readiness adapter.
