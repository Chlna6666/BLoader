# BLoader 0.2.62

## 跨账号 Xbox 认证恢复

0.2.61 已确认同账号可以完整复用 Microsoft Gaming Runtime，但跨账号时只有 XUID/Gamertag 元数据被 BMCBL 覆盖，PlayFab/Xbox Live/Realms 等 Token 请求仍属于系统 backing user，因此必须失败关闭。

0.2.62 将认证拆成两条明确路径：

- **同账号**：当 native backing XUID 与 BMCBL XUID 一致时，继续直接调用 Microsoft Runtime 的 `XUserGetTokenAndSignature*`，DToken、TToken、XSTS、缓存和 Signature 全部保持官方。
- **跨账号**：当 XUID 不一致时，不再只暴露自定义名称后让服务请求失败。BLoader 改用 BMCBL 已完成预认证的 Profile/PlayFab/Multiplayer/Realms/Licensing XSTS，并使用同一 BMCBL Device PoP P-256 key 为业务请求生成 Signature。

BMCBL 原始 XASU UToken 仍随一次性安全会话进入 BLoader，供后续研究真正的 Microsoft Runtime pre-XSTS 用户凭据注入点；当前跨账号兼容路径不会伪称这些最终 XSTS/Signature 来自 Microsoft Runtime。

## 安全边界

- MSA refresh token 仍只保存在 BMCBL，不进入 Minecraft。
- 启动凭据继续通过 PID 绑定、父进程校验、SHA-256 校验的一次性 named pipe 传递。
- UToken、XSTS、UHS、P-256 private blob 和 Signature 正文均不写入日志。
- 如果跨账号 fallback Token 已过期或缺失，继续 fail-closed，不会回退到系统 backing user 的 XSTS。

## 预期日志

同账号：

```text
route=same-account-native
DToken=official | TToken=official | XSTS=official | signature=official
```

跨账号：

```text
route=cross-account-bmcbl-preauth
跨账号 Token 请求使用 BMCBL 预认证回退
final_xsts=bmcbl-preauth | signature=bmcbl-device-key
```
