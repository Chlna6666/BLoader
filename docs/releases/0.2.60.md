# BLoader 0.2.60

## UToken-only 启动协议诊断修复

本版本继续保持 BMCBL / BLoader / Microsoft Gaming Runtime 的职责边界：

- BMCBL 只向 Minecraft 进程交付目标账号的 XASU UToken 与公开身份元数据；
- BLoader 只在微软 Runtime 的 DToken + TToken + UserTokens 聚合请求中替换 UserTokens；
- 最终 XSTS、缓存刷新和 HTTP Proof-of-Possession Signature 仍由官方 xgameruntime.dll 完成。

## 修复

1. 修正旧 BLoader 与新 UToken-only payload 混用时的误导日志。serde 的字段缺失/类型不匹配现在报告为 `utoken-schema-mismatch`，不再统一伪装成 `payload is not valid JSON`。
2. JSON 语法错误、截断和 schema mismatch 分开记录，并仅输出错误类别与位置，不输出 UToken、UHS、XSTS 或 Signature 正文。
3. payload 继续直接反序列化到 `WireDocument`，避免先解析到 `serde_json::Value` 后产生额外的 UToken 明文堆副本。
4. 新增当前 BMCBL UToken-only schema 的单元测试，覆盖 `auth_mode`、XUID/Gamertag、UToken 和 expiry 字段。

## 版本兼容

BLoader 0.2.56 仍使用旧的 full-preauth schema，要求 `ecc_private_blob_b64`、预生成的多个 XSTS token 等字段，不能与当前 BMCBL 的 UToken-only payload 混用。BMCBL 必须同步嵌入本版本或更新版本的 BLoader.dll。
