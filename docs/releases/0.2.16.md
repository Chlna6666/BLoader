# BLoader 0.2.16

## Pre-Main Gate

This release prevents Minecraft's original entry point from racing BLoader's critical preload chain during static PE-import startup.

### Added

- Added a process-start-only Pre-Main Gate for BLoader's static PE import path.
- During `DLL_PROCESS_ATTACH`, BLoader resolves the host PE `AddressOfEntryPoint`, installs a dedicated first-priority VEH, saves the original first byte, and temporarily replaces it with a one-byte `INT3`.
- Dynamic/late `LoadLibrary` attachment is excluded automatically using the documented `DllMain` `lpvReserved` static-load signal.
- The Minecraft startup thread restores the original OEP byte when it reaches the gate and waits before executing the original first instruction.
- A 90-second fail-closed watchdog terminates the process rather than allowing a still-running preload/allocator replacement to race Minecraft main initialization.

### Changed

- `bloader-bootstrap` now performs the entire critical pre-main phase before releasing Minecraft OEP.
- Priority `type: "preload"` / `PreLoader.dll` remains the first third-party DLL loaded after `DllMain` returns and the Windows loader lock is released.
- When PreLoader succeeds, it retains ownership of the remaining preload chain and BLoader skips the legacy native preload pass.
- When PreLoader is missing or fails, BLoader completes the legacy `native` / `preload-native` fallback before releasing Minecraft OEP.
- Config, global logger, debug console, process-wide stdio capture, render/network hooks, and ordinary Mods remain post-gate initialization and do not delay the critical pre-main release.

### Fixed

- Fixed the race where Minecraft could execute its original entry point concurrently with an 11+ second PreLoader/LeviLamina initialization.
- Prevents Minecraft objects from being allocated with the original Bedrock allocator while LeviLamina is still replacing `Bedrock::Memory::getDefaultAllocator`, reducing the cross-allocator `mi_free` crash path observed after late LeviLamina initialization.
- Avoids loading third-party DLLs directly from BLoader `DllMain`; the gate only performs minimal PE/VEH setup under loader lock, while `LoadLibraryW` remains on `bloader-bootstrap` after loader-lock release.

### Diagnostics

New bootstrap markers include:

- `premain-gate.armed mode=oep-int3`
- `dllmain.premain-gate static_attach=... armed=...`
- `bootstrap.preloader.premain.begin`
- `bootstrap.preloader.premain.done`
- `bootstrap.native_preload.premain.begin`
- `bootstrap.native_preload.premain.delegated`
- `bootstrap.native_preload.premain.done`
- `premain-gate.release reason=critical-preloads-ready`
