# BLoader 0.2.96 — 原生 Mod / 游戏控制台日志归因

本次修复的根因：BLoader 只 hook 了 `kernel32` 的 `WriteConsoleW/A` 与 `WriteFile`，
而游戏与多数现代 DLL 通过 `api-ms-win-core-*` API Set（解析到 `kernelbase`）写入，
LeviLamina 的 ucrt 输出最终也落在 `kernelbase`。因此控制台里的原生输出一条都没被捕获。

## 变化

- 控制台写入钩子同时覆盖 `kernel32` 与 `kernelbase`，并对两个模块解析到同一函数体的情况去重；
  嵌套调用只由最外层 detour 捕获，避免同一行记录两次。
- 每条捕获行按**调用者模块**归因，而不是按文本猜测：
  - 游戏本体、随游戏分发的 DLL、`xgameruntime` / `libHttpClient` → `[Minecraft]`
  - `mods/` 下的 DLL → 紫色 `[Mod 名]`（优先使用 manifest 注册名）
  - 其余 Windows 组件 → `[System]`，默认 info 级不显示，`log_level=debug` 时可见
  - BLoader 自身 → 不再回环捕获
- 捕获到的行同时写入 `logs/latest.log` 与归档日志（保留原始时间戳），不再只存在于控制台。
- 初始化时不再清空共享的 `logs/latest.log`：LeviLamina 在同一文件写入并负责轮转，
  清空会破坏它已写好的启动横幅，并让它按旧偏移继续写（稀疏 NUL 字节）。
- `log_level=debug/trace` 现在同时作用于控制台；此前只抬高文件 Sink。
- 控制台钩子按 hook 单独启用，失败可重试；ANSI（`WriteConsoleA`）输出按系统代码页解码。

## 预期输出

```text
[20:51:54 INFO] [Minecraft] Runtime Service struct SErrorImpl Created
[20:51:54 INFO] [LeviLamina] 正在加载模组……
[20:51:54 INFO] [LeviLamina] 已加载 0 个模组
```

## 验证

- `cargo test --lib`：134 项通过（新增来源归因 6 项、ANSI 解码 1 项）。
- 实机验证：LeviLamina 启动横幅、`[Server]` 游戏日志与游戏 ContentLog 应同时出现在
  控制台与 `logs/latest.log`；`xgameruntime` 不再显示为 Mod。
