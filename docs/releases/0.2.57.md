# BLoader 0.2.57

## Xbox / XUser 混合认证

本版本将 Windows Minecraft 的 Xbox 认证职责重新划分为：

- **BMCBL**：仅向 Minecraft 进程传入目标账号的原始 XASU `UToken` 与公开用户元数据；MSA refresh token 继续只保存在启动器进程/凭证存储中。
- **Microsoft Gaming Runtime / xgameruntime.dll**：继续建立官方 backing XUser，负责 Windows Device/Title 上下文、最终 XSTS、Token cache/ForceRefresh 以及 HTTP Proof-of-Possession Signature。
- **BLoader**：对 Minecraft 暴露 BMCBL 选择的 XUID/Gamertag，同时复用微软官方 XUser handle 和生命周期；在官方 XSTS 请求签名前只替换 `Properties.UserTokens`，保留官方 `DeviceToken`、`TitleToken`、RelyingParty 与签名上下文。

## 主要变化

1. BLoader 安全一次性管道不再消费 BMCBL 预生成的 Profile/PlayFab/Multiplayer/Realms/Licensing XSTS，也不再导入 BMCBL P-256 私钥。
2. XUser Add/handle/state/change-event/sign-out 路径委托 System32 `xgameruntime.dll` 的原生 provider，BLoader 只覆盖对 Minecraft 可见的账号身份元数据。
3. `XUserGetTokenAndSignature*` 改为委托微软原生 provider，不再由 BLoader 拼接 `XBL3.0` Authorization 或自行生成最终服务 Signature。
4. 新增 XSTS UToken 注入桥：在 BCrypt 签名输入与 WinHTTP 发送体两个阶段识别同时包含 `DeviceToken`、`TitleToken`、`UserTokens` 的 XSTS 请求，只替换第一个用户 Token。
5. 引入签名票据配对：只有确认官方 BCrypt 签名阶段已经对同一原生 UToken 进行了替换，HTTP 阶段才允许发送对应重写后的请求；无法配对时失败关闭，避免发送“修改了 body 但 Signature 仍属于旧 body”的请求。
6. WinHTTP 流式写入仅在替换前后长度一致时允许原位语义重写；长度改变时失败关闭，避免破坏已提交的 Content-Length/total length。

## 运行时日志

成功路径会出现类似诊断：

```text
微软官方 XUser backing provider 已绑定
官方 backing XUser 已建立
官方 XSTS UToken 注入桥已安装
官方 XSTS 签名输入已替换 UToken
官方 XSTS UToken 签名票据已生成
官方 XSTS HTTP 请求已替换 UToken
```

日志不会输出 UToken、最终 XSTS、UHS 或 Signature 正文。

## 已知边界

- 该实现要求目标系统的官方 Gaming Services/xgameruntime 能建立一个原生 backing XUser。完全没有可用 Windows/Xbox 用户的机器是否仍能由官方 Runtime 单独建立 Device/Title 认证上下文，需要在真实 Minecraft for Windows 环境验证。
- `xgameruntime.dll` 的 XSTS 网络/签名实现属于微软 Runtime 内部行为。当前桥按 BCrypt + WinHTTP 路径失败关闭；如果某个 Gaming Services 版本改用其他传输或签名实现，日志会显示注入阶段未命中，不能将其视为已替换成功。
- 当前启动管道仍是一次性 UToken 交付。长时间运行到 UToken 本身过期时，后续版本应增加 BLoader ↔ BMCBL 进程期 UToken refresh 控制通道；MSA refresh token 不应进入 Minecraft 进程。
