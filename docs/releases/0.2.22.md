# BLoader 0.2.22

## UWP-safe bootstrap isolation

This release removes three startup hazards that remain active even when file redirection is disabled.

### XUser bridge no longer runs under the Windows loader lock

`DllMain` now only records that XUser initialization is deferred. The authenticated one-shot BMCBL session, official System32 `xgameruntime.dll` load, and QueryApiImpl MinHook installation run in the OEP-gated pre-main phase after `DllMain` has returned. The bridge is still ready before Minecraft executes its original entry point.

### Disabled network features no longer install WinSock hooks

When both `enable_network_hooks=false` and `enable_p2p_redirection=false`, BLoader does not load ws2_32 for itself, create the 17 WinSock detours, or call `MinHook::enable_all_hooks()` for the network subsystem. Previously the detours were installed even though runtime logging/redirection behavior was disabled.

### Global CRT/stdout capture moves after Minecraft OEP

For the static PE-import launch path, `ucrtbase.dll`/`msvcrt.dll` fd rebinding and optional debug-console allocation are deferred until 1500 ms after OEP release. This prevents BLoader from mutating process-wide CRT/stdout state before Minecraft's executable CRT and AppModel startup have initialized. Late/dynamic attachment keeps the immediate capture path because the host is already running.

New bootstrap markers distinguish the phases:

- `dllmain.xuser_bridge.deferred`
- `bootstrap.xuser_bridge.premain.begin/done`
- `bootstrap.runtime_io.deferred`
- `post-oep.runtime_io.ready`
- `[net-hook] Hook installation skipped...`

The UWP crash must still be verified in a real Minecraft launch; CI validates build/test behavior, not AppModel runtime compatibility.
