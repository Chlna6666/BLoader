# BLoader 0.2.72

## XUser / Auth 边界重构

- 明确将 BLoader 的 synthetic XUser(B) 作为唯一公开用户身份；Microsoft Runtime 不再被描述或使用为 B 的 backing user。
- 正常 `XUserGetTokenAndSignature*` 转发路径新增 `SameIdentityNativeCapability` 类型门槛：只有经过 XUID 验证、与 B 完全相同的 native XUser 才能进入官方最终 Token 快速路径。
- 不同系统账号 A 与无系统账号两种场景统一进入 Virtual XUser + pre-XSTS Auth Adapter 路径；在 ABI 尚未解析前继续 fail-closed。
- pre-XSTS 诊断中临时取得的 native A 只用于触发 Microsoft Runtime 的 DeviceToken / TitleToken / UserTokens 聚合路径，明确禁止作为 B 的身份对象，也禁止把 A 的最终 XSTS 返回 Minecraft。

## 目标认证模型

```text
BMCBL                  BLoader                     Microsoft Runtime
  |                       |                                |
  |-- XUID/Gamertag B --->|-- Virtual XUser(B) ----------> Minecraft
  |-- raw UToken(B) ----->|                                |
  |                       |-- pre-XSTS Auth Adapter ------> DToken (official)
  |                       |                                TToken (official)
  |                       |-- UserTokens = UToken(B) ----> XSTS authorize
  |                       |<------------------------------- XSTS(B)
  |                       |<------------------------------- Signature (official)
```

DToken / TToken 被视为设备与 Title 认证能力，不再按“native A 的用户 Token”处理；真正决定用户身份的是进入 `UserTokens` 的 B UToken 以及最终服务端签发的 XSTS。

## 诊断与安全边界

- 新日志增加 `identity_owner=bloader-virtual-xuser`、`microsoft_runtime_role=auth-capability-only`、`native_user_is_backing_identity=false`、`native_final_xsts_reuse=false` 与 native identity relation。
- 有系统账号 A 时允许其仅作为透明 capability probe 的触发条件；探针结果继续丢弃且不读取 token body。
- 无系统账号时不会触发交互式 Microsoft 登录 UI；Virtual XUser(B) 仍保持独立存在。
- UToken、XSTS、Signature 与请求正文仍不会写入日志。
