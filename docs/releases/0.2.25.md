# BLoader 0.2.25

Diagnostic UWP startup isolation release.

For this release the library entrypoint is intentionally replaced with `src/diagnostic_minimal.rs` so the normal BLoader runtime is not compiled into the primary DLL entry path.

On `DLL_PROCESS_ATTACH`, `DllMain` only:

1. Resolves the current executable path with `GetModuleFileNameW(NULL, ...)`.
2. Calls `SetCurrentDirectoryW` with the directory containing `Minecraft.Windows.exe`.
3. Returns `TRUE` immediately.

This diagnostic build does not install the OEP gate, VEH/crash handlers, tracing/logging, stdio capture, XUser bridge, MinHook, file/network hooks, configuration, runtime readiness, Mod/preload loading, or worker threads.

The purpose is to distinguish a static PE-import compatibility problem from a BLoader runtime-initialization problem on legacy UWP versions such as Minecraft 1.18.30.
