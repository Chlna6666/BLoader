# BLoader 0.2.18

This release hardens the UWP/Win32 file-redirection layer for Minecraft versions that use different file API paths.

## File redirection

- Added native `ntdll` fallback coverage for `NtCreateFile`, `NtOpenFile`, `NtDeleteFile`, `NtQueryAttributesFile`, `NtQueryFullAttributesFile`, and absolute rename targets through `NtSetInformationFile`.
- Added additional path-bearing Win32 hooks including `CreateDirectoryExW`, `FindFirstFileW`, `MoveFileW`, and `ReplaceFileW` while retaining the existing Win32 and `FromApp` coverage.
- Removed `std::fs::create_dir_all` from file detours. Redirect targets are prepared once before hooks are enabled, so hooked file operations no longer recursively perform filesystem work.
- Added a TLS re-entry guard so BLoader logging and nested runtime file calls bypass redirection safely while a redirect detour is already executing on the same thread.
- Preserved incoming `\\?\` and `\??\` path namespaces, including UNC conversion, instead of stripping long-path semantics from redirected paths.
- Added lexical Windows path canonicalization for slash normalization, duplicate separators, `.` and `..` components before rule matching.
- Redirect rules are sorted by longest source path first; more specific rules now override broad parent-directory rules deterministically.
- Replaced Unicode-expanding lowercase matching with byte-stable ASCII case folding for Windows path keys, avoiding suffix slicing against a differently sized lowercased string.

## Diagnostics

- Startup logs now list every active redirect rule and its priority.
- Hook installation logs report available/unavailable APIs and the final coverage summary.
- Actual redirect operations emit debug records with sequence number, API name, source path, and target path.
- Per-process redirect detail logging is capped at 4096 events to avoid unbounded log growth; a warning is emitted when the cap is reached.
