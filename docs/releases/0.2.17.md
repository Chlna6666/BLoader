# BLoader 0.2.17

## Single-thread pre-main startup

BLoader's static BMCBL launch path no longer uses a separate `bloader-bootstrap` worker to initialize PreLoader while Minecraft's startup thread waits at the OEP gate.

The new sequence is:

1. `DllMain` installs only the one-byte OEP `INT3` gate and the VEH while the Windows loader lock is active.
2. `DllMain` returns without loading third-party DLLs and without creating the normal bootstrap worker.
3. Minecraft's original startup thread reaches the OEP and hits the gate.
4. The VEH restores the original OEP byte.
5. On that same Minecraft startup thread, BLoader synchronously runs the immediate startup chain, beginning with priority `PreLoader.dll`, its delegated preload chain, legacy native preload fallback when required, and BLoader immediate Mod/bootstrap work.
6. Only after the synchronous sequence completes does the VEH resume the original Minecraft OEP.

This removes the previous two-thread startup relationship where Minecraft's startup thread and `bloader-bootstrap` were distinct execution contexts during critical preload initialization.

For static BMCBL launches, failure to arm the OEP gate is now fail-closed instead of silently falling back to a concurrent bootstrap worker. Dynamic/late `LoadLibrary` attachment keeps a compatibility worker because true pre-main ordering is no longer possible once the executable has passed its entry point.

## Diagnostics

New bootstrap markers include:

- `premain-gate.armed mode=oep-int3-inline-single-thread`
- `premain-gate.hit execution=inline-single-thread`
- `bootstrap.inline.start execution=minecraft-startup-thread`
- `bootstrap.mods.load.begin ... serial=true`
- `bootstrap.sequence.complete`
- `premain-gate.complete ... bootstrap_completed=true`

The change was motivated by a 0.2.16 crash report in which the Minecraft startup thread and the BLoader bootstrap thread were different, while the final LeviLamina access violation occurred on the BLoader bootstrap thread after the pre-main gate had already completed.
