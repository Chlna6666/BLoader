# BLoader 0.2.73

## pre-XSTS ABI 自举

- 修复 0.2.71/0.2.72 已定义 `install_call_target_probes` 但未调用，导致 direct-call 候选从未真正安装探针的问题。
- call-target 探针现在优先覆盖 `UserTokens` xref 后的 helper，并使用剩余槽位覆盖 builder 内其他唯一 helper。
- 增加安全的参数 marker hint，只报告 `UserTokens` / `DeviceToken` / `TitleToken` 所在参数或一级间接指针，不输出 Token 内容。
- 对直接传入的完整 pre-XSTS JSON 文档进行保守 ABI 自举：仅当同一文档同时包含 `UserTokens`、`DeviceToken`、`TitleToken` 时，替换 `UserTokens` 数组为 BMCBL 的 B UToken，保留微软官方 DToken/TToken。
- 自动识别可选的长度参数；替换缓冲区仅在 helper 调用期间存活并在释放时清零。

## B != A

- 诊断阶段取得的 silent native XUser 只缓存为 Microsoft Runtime 认证能力句柄，不成为 BLoader 的公开/背后用户身份。
- ABI 自举成功后，后续 `XUserGetTokenAndSignature*` 可使用 native A 触发微软官方 DToken/TToken/XSTS/Signature 链，而 pre-XSTS hook 在 `xsts/authorize` 前把 `UserTokens(A)` 替换成 `UToken(B)`。
- ABI 未解析时仍 fail-closed，绝不返回未经替换的 A 最终 XSTS。

## 无系统账号

- Synthetic XUser(B) 继续完全可建立且不触发系统登录 UI。
- 当前版本仍不会伪造 Microsoft native XUser。若 Windows 没有任何 silent native capability user，则没有安全的官方 D/T 请求触发上下文，Token 路径继续 fail-closed。后续需在已确认的 Runtime ABI 上继续下探到不依赖 native XUser 的 Device/Title capability provider。

## 安全

- 日志不输出 UToken、A Token、XSTS、Signature、JSON 正文或请求正文。
- ABI 仅在真实 helper 调用成功返回后标记 ready；无法确认完整 D/T/U 聚合文档时透明转发，不做修改。
