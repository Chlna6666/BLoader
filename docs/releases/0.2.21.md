# BLoader 0.2.21

## Fix UWP LocalState redirection startup failure

BLoader now materializes missing target parent directories immediately before redirected CreateFile operations that can create a file (`CREATE_NEW`, `CREATE_ALWAYS`, or `OPEN_ALWAYS`). Pure read/open-existing calls do not create directories.

This addresses the UWP startup sequence where Minecraft probes an existing LocalState directory and then creates `games/com.mojang/minecraftpe/hs` under the per-version redirected root. The previous implementation only created the redirection root itself, so the nested target path could fail with `ERROR_PATH_NOT_FOUND` and Minecraft could terminate without raising a catchable unhandled exception.

Redirected CreateFile/CreateFileFromApp/CreateFile2 calls now also log the effective target, creation disposition, success handle, or Win32 error while preserving the caller-visible last-error value.

The existing TLS re-entry guard remains in force, so parent materialization uses the original filesystem APIs and is not recursively redirected.
