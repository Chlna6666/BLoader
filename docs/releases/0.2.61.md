# BLoader 0.2.61

## Xbox / XUser 原生 Token 路由修复

本版本修复 0.2.60 在官方 backing XUser 与 BMCBL 选择账号本来就是同一 XUID 时仍强制要求观察 UToken 重写，从而把 Microsoft Runtime 已成功返回的 `S_OK` 错误改成 `E_FAIL`、导致 Minecraft 无法登录的问题。

## 修复

1. 在调用官方 `XUserGetTokenAndSignature*` 前，通过微软原生 IXUser base slot 11 读取 backing XUID，并与 BMCBL 会话 XUID 比较。
2. **同账号**：直接委托 Microsoft Runtime，保留调用方原始 options，不再额外强制 `ForceRefresh`，也不再要求 BCrypt/WinHTTP UToken rewrite。DToken、TToken、XSTS、缓存与 Signature 全部继续由微软 Runtime 处理。
3. **跨账号**：继续 fail-closed。不会把 backing user 的 XSTS 返回给 Minecraft 后再伪装成 BMCBL XUID，避免 Profile/XUser 身份与 Achievements/Presence/Multiplayer 实际认证用户分裂。
4. 停用 0.2.60 的 BCryptHashData + WinHTTP XSTS 注入路径作为默认正式路径。实机日志已经证明当前 Windows Gaming Runtime 的 Token refresh 可以成功返回而不经过 Minecraft 进程中的这些 XSTS body Hook，因此不能把“未命中”当作 Token 失败。
5. 同一 RelyingParty 的身份路由只记录一次，避免旧实现因每次 Token 请求强制刷新而产生大量重复 warning。

## 诊断日志

同账号正常路径会出现：

```text
官方 Token 身份与 BMCBL 账号一致；直接复用 Microsoft Runtime
route=same-account-native
DToken=official
TToken=official
XSTS=official
signature=official
forced_refresh=false
```

跨账号在当前版本会明确输出：

```text
跨账号官方 Token 请求被拒绝
reason=current-gaming-runtime-xsts-path-not-observable-in-process
action=fail-closed
```

不会再出现 0.2.60 中对同账号反复输出的 `custom-utoken-rewrite-not-observed`。

## 当前边界

UToken-only 启动协议保持不变。BMCBL 仍只向 BLoader 传递目标账号 XASU UToken 与公开用户元数据，MSA refresh token 不进入 Minecraft 进程。

对于真正的跨账号切换，仍需要找到 Windows Gaming Runtime 在最终 XSTS 生成前可验证的用户身份注入边界；在此之前不允许把系统 backing user 的官方 Token 当成另一个 BMCBL 用户使用。
