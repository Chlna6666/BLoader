# BLoader 0.2.65

## XUser 不再依赖 Windows 系统账号

0.2.65 将 BMCBL XUser 与 Windows native XUserHandle 解耦。Minecraft 看到的 XUserHandle 现在由 BLoader 自己维护，`XUserAddAsync`、`XUserAddResult`、`FindUserById`、`FindUserByLocalId`、`DuplicateHandle`、`GetState`、`GetId`、Gamertag 与注销生命周期均不再要求 Windows 已登录 Xbox 用户。

这解决了此前架构中的结构性限制：Windows 没有 Xbox 系统账号时，BMCBL 用户仍可以正常建立 SignedIn XUser 会话，而不会触发系统账户 Bootstrapper。

## UToken-only v3

BLoader 启动协议更新为 `official-runtime-user-token-v3`。Minecraft 进程只接收：

- BMCBL 账号 XUID / Gamertag / AgeGroup / Privileges；
- 原始 Xbox XASU UToken；
- UToken 过期时间。

不再接收 MSA access token、MSA refresh token、预生成 XSTS 或自定义 PoP 私钥。0.2.64 的 native MSA slots 39/40/41 覆盖器已删除。

## Microsoft Runtime 能力边界

如果 Windows 已经存在一个与 BMCBL XUID 完全一致、且可以由官方 `FindUserById` 无 UI 找到的 native XUser，BLoader 仅把该隐藏 native handle 用作同账号官方 Token 快速路径。BLoader 的公开 XUserHandle 仍保持独立。

如果系统账号不同或完全不存在，BLoader 不会调用官方 `XUserAddAsync`，也不会借用其他账号的 XSTS。跨账号 Token 请求在真正的 pre-XSTS User identity provider 被解析前继续 fail-closed。

## pre-XSTS Runtime 探针

新增只读 PE 探针，对已加载的 System32 `xgameruntime.dll` 查找：

- `UserTokens`
- `DeviceToken`
- `TitleToken`
- `xsts/authorize`
- `xsts.auth.xboxlive.com`

探针只扫描 PE 的可读/可执行 section，并查找 `.text` 中指向这些字符串的 x64 RIP-relative `LEA` 引用。日志仅输出 RVA、数量和候选状态，不输出任何 UToken/XSTS/Signature 内容。

当前阶段的目的，是在真实 Minecraft/Gaming Runtime 版本上确定 `D + T + U -> XSTS` 的实际 builder 所在模块和候选调用点，再在 ABI 被验证后接入 BMCBL UToken。未知 ABI 不会被猜测 Hook。

## 安全边界

- BMCBL refresh token 始终留在启动器进程。
- 不向 Minecraft 传递 MSA access token。
- 不允许系统账号 A 的最终 XSTS 以 BMCBL 账号 B 的身份返回。
- 未解析 pre-XSTS 注入点时保持 fail-closed。
